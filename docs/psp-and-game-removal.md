## PSP engine

Use mature **PPSSPP 1.20.4** libretro core, upstream release source **`fa50bb1976065c4f8b1b47af227d367fe9771555`**, GPL-2.0-or-later, with pinned submodule identities. The linked Home/Ubuntu profile is distributed under **GPL-3.0-or-later**, accommodating its linked GPLv3 and compatible components; data and dependency notices remain separate. Build an explicit **software renderer / backend None / native 480×272 / JIT** profile. Existing RetroArch→FFmpeg→MediaMTX authenticated Standard publication and Home input/save boundaries are reused, not replaced with a new emulation engine or external management application.

Core, asset/font/VFPU data, source/build/license records live in a separate `PspRuntime` package. The immutable seven-system native runtime and hash-bound save/settings identities are untouched. Software assets are not Sony BIOS files or games. The source build uses Ubuntu shared FFmpeg; exact linked corresponding-source/notices closure is now qualified and remains checked during image construction. A narrow Linux memory-backing adaptation uses a private anonymous `memfd` instead of exhausting Docker's default 64-MiB `/dev/shm` with PSP-2000 RAM. Modified source and the patch/build recipe are retained in the corresponding-source archive; no CasaOS host memory/volume settings are changed.

The original `.info` declares hardware capabilities. Home may route this one core as CPU-frame output only when the **specific pinned package's software video/input/state/codec proof matches its binary and the existing frontend**. General GPU-core authorization is not widened. Required options force None/software/1x and disable ISO precache, cheats and networking; these are Home-managed options in this bundled Linux profile rather than editable controls that would be ignored. PSP can be visible in import/settings without claiming a missing/unqualified package is playable. Bundled-profile core/firmware views do not falsely require a GPU or user BIOS/helper upload.

Existing Selkies core hashes remain separately verified; PSP initially uses **Standard**, without changing a browser/profile's saved Selkies choice for its other games. An explicit PSP+Selkies launch is refused instead of running an unqualified publisher. PSP+Selkies, real GPU acceleration, Vita/PS2, commercial-game/device compatibility and old-host performance are not claimed. The user owns real game/PC/TV testing. No internet ROM/BIOS/game/media download is used for verification.

## Disc identity/correction

ISO alone is not a console identity. Extend bounded ISO9660 sampling to require structured **PSP_GAME directory + UMD_DATA.BIN file** markers. Preserve PS1/PS2 boot-file detection, raw-sector handling and 512-KiB sampling boundaries. Server upload validates strong ISO identity too: manually selecting PS1 cannot publish a positively identified PSP ISO as PS1.

For an earlier wrong import, **Correct to PSP** requires owner confirmation, no active game, full existing managed-copy integrity and actual PSP markers. A verified idempotent PSP copy is published before changing its system. The opaque game id, user state, favorites, manual presentation and old save partitions remain unchanged. Default core selection becomes PPSSPP; PS1 states are never loaded into PSP. Existing conflicting PSP records are refused rather than auto-merged. Old managed copies are retained conservatively; source-collection bytes are never moved/deleted.

Metadata that does not match the new platform is ignored, not deleted. Optional automatic metadata refresh can then match PSP; manually edited presentation remains authoritative.

## Game removal

- Owner/acquisition permission and **explicit confirmation** are required. Default/only exposed mode preserves saves, progress, artwork and metadata. Separate save deletion is not silently inferred.
- Durable `game-uninstall` work validates identity and exact managed file size/hash; unknown/conflicting files are retained. Active game or active installation blocks removal. Pending work fences launch/re-add/import of its shared payload.
- Remove only the requesting profile's library membership. A ROM's system/hash payload stays while another profile retains a reference. Last-reference removal targets declared managed game/disc files only; original uploaded-from/source-library files are never touched.
- A retained ROM with a missing preference row is treated conservatively as a live reference. Confirmed removal creates/updates only the requesting profile's membership row; it does not infer that another profile's missing row authorizes shared-file deletion.
- Re-import after completed uninstall reactivates the **same opaque game id** and retained favorites/saves. Ordinary duplicate import still preserves intentional library-hide preferences; completed uninstall reactivation is recorded separately.
- Downloaded web packages use managed game-library paths only. Immutable shipped web packages are profile-removed, not deleted from the image. Whole managed web folders move atomically into the job's trash before asset deletion, so restart cannot encounter a half-deleted manifest in the normal game catalog. Unknown extra files refuse that move.
- Applying removal cannot be cancelled after filesystem commit starts; interrupted work is retryable with its declared file list and existing product-job recovery. No broad folder deletion, source-media deletion, core uninstall, unrelated app removal or save reset is performed.
